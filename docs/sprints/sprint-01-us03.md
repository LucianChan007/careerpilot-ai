# Sprint 1 - US03 完成与验收记录

## 1. User Story

**US03：JD 输入与结构化解析**

作为大学生求职者，我希望输入岗位 JD 后，由 AI 自动提取岗位结构化信息，从而降低手动阅读和整理岗位要求的成本。

## 2. 实现内容

### 后端

- 新增 `backend/app/jd_schema.py`
- 新增 `backend/app/jd_service.py`
- 新增 `POST /api/jd/parse`
- 使用 LLM 对 JD 进行结构化解析
- 对 JD 空内容、过短内容和过长内容进行校验
- 使用 Pydantic 规范 API 请求结构

### 前端

- 新增 `backend/static/jd.html`
- 支持输入岗位 JD
- 支持填入示例 JD
- 支持调用 AI 进行解析
- 支持展示结构化 JD 结果卡片
- 支持查看岗位名称、公司、地点、学历、实习要求、专业要求、技能要求、经验要求、岗位职责和其他要求
- 支持查看原始 JSON

## 3. 接口测试

测试接口：

`POST /api/jd/parse`

测试结果：

- HTTP 状态码：200
- 成功解析岗位名称
- 成功解析工作地点
- 成功解析学历要求
- 成功解析技能要求
- 成功解析经验要求
- 成功解析实习周期

## 4. 前端测试

测试页面：

`http://127.0.0.1:8000/jd`

测试流程：

输入 JD → AI 解析 → 展示结构化岗位信息。

测试结论：

**通过。**

## 5. 自测发现的问题

在测试示例 JD 时发现，薪资信息“100-200元/天”存在被模型归入岗位要求字段的风险。

该问题可能导致后续岗位硬性条件匹配出现错误，因此未继续堆叠在 US03 内处理，而是将其作为 US04 迭代需求。

## 6. 迭代处理

在 US04 中：

1. 新增 `salary` 字段。
2. 修改 JD 结构化 Prompt，明确薪资单独提取。
3. 明确薪资不属于硬性条件。
4. 明确薪资不参与岗位匹配。

经重新测试，薪资能够独立显示，不再作为硬性条件参与匹配。
