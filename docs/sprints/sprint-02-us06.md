# Sprint 02 - US06 项目 / 实习经历与岗位工作内容匹配

## 1. User Story

**US06：分析项目 / 经历与岗位匹配程度**

作为一名正在寻找实习岗位的大学生，我希望 CareerPilot AI 能够根据岗位工作内容，分析我的项目经历和实习经历与岗位职责之间的匹配程度，从而了解哪些经历能够支撑岗位要求，以及当前存在什么经历缺口。

---

## 2. 优先级与 Sprint

- 优先级：P0
- Story Points：5
- Sprint：Sprint 2
- 状态：Done

---

## 3. 验收标准

### AC1：识别岗位工作内容

系统能够读取结构化 JD 中的 `responsibilities` 字段，并逐项分析岗位工作内容。

### AC2：读取用户项目经历

系统能够读取用户个人画像中的项目经历，并将项目内容作为经历匹配依据。

### AC3：读取用户实习经历

系统能够读取用户个人画像中的实习经历，并将实习内容作为经历匹配依据。

### AC4：岗位工作内容逐项匹配

系统能够将每一项岗位工作内容与用户已有项目、实习经历进行对应分析。

### AC5：输出匹配状态

每项岗位工作内容能够输出明确的匹配状态，包括：

- 匹配
- 部分匹配
- 信息不足 / 不匹配

### AC6：显示对应经历

对于匹配或部分匹配的岗位工作内容，系统能够展示对应的项目或实习经历。

### AC7：给出匹配依据

系统能够结合用户个人画像中的技能、项目描述和实习描述，说明岗位工作内容与已有经历之间的对应关系。

### AC8：明确经历缺口

当用户没有相关项目或实习经历时，系统能够明确指出“未发现相关经历”或对应经历缺口，而不是编造经历。

### AC9：禁止虚构经历

系统只能依据用户已有个人画像进行分析，不允许生成简历中不存在的项目、实习或工作经历。

### AC10：输出整体结论

系统能够根据各项岗位工作内容的匹配结果，给出整体经历匹配结论和总结。

## 4. 实现内容

### 后端

新增：

- `backend/app/experience_schema.py`
- `backend/app/experience_service.py`

其中：

`experience_schema.py` 定义 US06 经历匹配结果的数据结构，包括：

- overall_status
- work_item_count
- matched_count
- partial_count
- unknown_count
- unmatched_count
- work_items
- gaps
- summary

`experience_service.py` 使用 LLM 对岗位职责与用户项目 / 实习经历进行语义匹配，并要求模型输出：

- 工作内容
- 匹配状态
- 对应经历
- 匹配依据
- 分析说明

同时明确禁止根据单纯技能相似度虚构经历。

### API

新增：

```text
POST /api/jd/experience-match
```

接口接收结构化岗位信息，读取当前保存的：

```text
backend/data/profile.json
```

然后调用经历匹配服务，返回：

```text
profile
job
experience_match
```

### 页面

新增：

```text
/experience
```

对应：

```text
backend/static/experience.html
```

页面用于展示：

- 综合经历匹配结论
- 岗位工作内容数量
- 匹配数量
- 部分匹配数量
- 信息不足 / 缺口数量
- 每项岗位工作内容
- 对应项目 / 实习经历
- 匹配依据
- 分析说明
- 经历缺口
- 匹配总结
- 原始 JSON

同时修改：

```text
backend/static/match.html
```

增加：

```text
分析项目 / 经历匹配
```

按钮，实现：

```text
/jd
↓
/match
↓
/experience
```

## 6. 实际测试结果

系统成功完成 3 项岗位工作内容分析：

- 匹配：1
- 部分匹配：2
- 信息不足 / 缺口：0

### 工作内容 1

**使用 C/C++ 语言进行软件开发，确保产品功能和质量。**

结果：

**部分匹配**

对应经历：

**网格交易回测与参数优化系统**

匹配依据：

用户具有 C++ 技能，同时项目中存在金融数据分析系统开发、系统测试、功能验证和缺陷修复经历。

但现有项目描述没有明确说明使用 C/C++ 语言完成该项目开发，因此不能直接判定为完全匹配。

系统最终将该项判定为“部分匹配”，没有将技能信息直接等同于具体项目技术栈。

### 工作内容 2

**与团队合作进行软件测试，确保产品达到质量标准。**

结果：

**匹配**

对应经历：

- 网格交易回测与参数优化系统
- 广州早知信息科技有限公司运维开发实习生

匹配依据：

项目中存在系统测试、功能验证、问题排查和缺陷修复经历；实习中存在功能验证、问题定位和 Bug 修复经历。

该项与用户已有经历存在明确对应关系，因此判定为“匹配”。

### 工作内容 3

**参与软件的整体架构设计，包括界面设计和数据库交互。**

结果：

**部分匹配**

对应经历：

- 校园体育空间行为数据采集与分析平台
- 广州早知信息科技有限公司运维开发实习生
- 网格交易回测与参数优化系统

匹配依据：

用户具有微信小程序数据采集流程设计、后台业务流程优化、页面展示问题处理以及系统开发经历。

但现有经历没有明确体现整体架构设计、界面设计或数据库交互，因此只能判定为部分匹配。

## 7. 经历缺口

系统最终识别出两个主要经历缺口：

### 缺口 1：C/C++ 软件开发经历

未发现明确使用 C/C++ 语言进行软件开发的项目或实习经历。

虽然用户个人画像包含 C++ 技能，但现有项目描述没有明确说明对应项目使用 C/C++ 开发，因此系统没有将技能直接当作项目证据。

### 缺口 2：整体架构 / 界面 / 数据库交互经验

未发现整体架构设计、界面设计或数据库交互的直接项目 / 实习证据。

现有经历主要体现为流程设计、后台业务流程优化、页面展示问题处理以及系统功能开发和排查，因此只能作为间接相关经历。
