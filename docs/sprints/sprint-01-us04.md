# Sprint 1 - US04 岗位硬性条件匹配

## 1. User Story

**US04：岗位硬性条件匹配**

作为大学生求职者，我希望系统能够将岗位 JD 中明确的硬性条件与我的个人画像进行匹配，从而快速判断自己是否满足岗位的基本要求。

## 2. 需求来源

US03 开发完成后的开发者自测。

在测试 C++ 开发实习 JD 时，发现薪资信息可能被错误归入岗位要求，因此在 US04 中完成字段分类修正，并进一步实现个人画像与岗位硬性条件匹配。

## 3. 实现内容

### JD 信息分类修正

- 新增 `salary` 字段
- 修改 JD 结构化 Prompt
- 明确薪资属于岗位信息
- 明确薪资不参与硬性条件匹配

### 岗位匹配后端

- 新增 `match_schema.py`
- 新增 `match_service.py`
- 新增 `POST /api/jd/match`
- 自动读取 `backend/data/profile.json`
- 使用当前个人画像与结构化岗位进行匹配

### 岗位匹配前端

- 新增 `match.html`
- 展示当前个人画像
- 展示岗位基本信息
- 展示岗位薪资
- 展示逐项硬性条件匹配结果
- 展示“满足 / 不满足 / 信息不足”
- 展示整体匹配结论
- 展示可能存在的能力 Gap
- 展示匹配依据

## 4. 完整业务流程

```text
真实简历
    ↓
US01：AI 解析个人画像
    ↓
profile.json
    ↓
US03：AI 解析岗位 JD
    ↓
结构化 job
    ↓
US04：个人画像 + 岗位
    ↓
硬性条件匹配
    ↓
逐项结果 + 整体结论
```

## 5. 验收测试

### 测试案例 A：C++开发实习生

测试岗位：

C++开发实习生

测试条件：

- 地点：广州
- 学历：学历不限
- 技能：C/C++、QT
- 经验：桌面开发经验
- 实习周期：5天/周3个月

测试个人画像：

陈韬真实个人画像。

测试结果：

系统成功读取真实个人画像，并对岗位学历、专业、技能、经验、地点和实习周期进行逐项判断。

同时，薪资“100-200元/天”单独作为岗位信息展示，不参与硬性条件匹配。

结论：

**通过。**

### 测试案例 B：高学历及工作经验要求岗位

测试岗位设置：

- 硕士及以上学历
- 计算机相关专业
- C++
- 3年以上相关工作经验
- 广州

测试结果：

系统能够识别用户学历和相关经历与岗位要求之间的硬性不匹配或信息不足，并生成整体匹配结论。

结论：

**通过。**
