# Sprint 1 - US04 岗位硬性条件匹配

## 1. User Story

**US04：岗位硬性条件匹配**

作为大学生求职者，我希望系统能够将岗位 JD 中明确的硬性条件与我的个人画像进行匹配，从而快速判断自己是否满足岗位的基本要求。

## 2. 需求来源

US03 开发完成后的开发者自测。

在测试 JD：

“C++开发实习生 / 100-200元/天 / 广州 / 5天/周3个月 / 学历不限……”

时，发现模型将“100-200元/天”错误放入岗位要求字段。

该问题可能影响后续岗位匹配，因此将其作为 US04 的优化点。

## 3. 本 Sprint 目标

1. 修正 JD 中薪资信息的字段分类。
2. 将薪资独立保存为岗位信息。
3. 明确薪资不属于硬性条件，不参与岗位匹配。
4. 实现用户个人画像与岗位学历、专业、技能、经验、地点、实习周期等条件的匹配。
5. 输出每项条件的匹配状态及依据。
6. 输出整体硬性条件匹配结论。

## 5. 验收标准

### JD 信息分类

测试 JD：

C++开发实习生
100-200元/天
广州
5天/周3个月
学历不限

预期：

- salary = 100-200元/天
- location = 广州
- internship_days = 5天/周3个月
- required_education = 学历不限
- salary 不出现在 other_requirements

### 岗位匹配

系统能够读取用户个人画像，与岗位硬性条件进行匹配，并对每项条件返回：

- 满足
- 不满足
- 信息不足

同时给出整体结论和匹配依据。
